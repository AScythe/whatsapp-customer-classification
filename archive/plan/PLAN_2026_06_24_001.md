# PLAN_2026_06_24_001

## Problem Statement

Create a new `decode_media_doc.py` script that decodes base64-encoded documents (PDF, DOC, DOCX, XLS, XLSX) from WhatsApp JSONL export files, following the same idempotent pattern as `decode_media_ptt.py`. Extract shared helper functions into a `media_utils.py` module to avoid duplication. Remove `application/pdf` from `decode_media_ptt.py` to give the new script exclusive ownership of document decoding.

## Goals & Non-Goals

### Goals
- New `decode_media_doc.py` decodes `type="document"` entries via `data:` URI base64 payload → local `media/doc_*` files
- Shared `media_utils.py` module extracted: `find_next_seq()`, `parse_data_uri()`, `get_type_prefix()`
- `decode_media_ptt.py` imports from `media_utils.py` and removes `application/pdf`
- Documentation updated: `README.md`, `AGENTS.md`, `docs/ARCHITECTURE.md`, `docs/SPECIFICATIONS.md`
- Idempotent: re-running shows "No new media to extract"
- All existing tests pass

### Non-Goals
- No new Python packages or dependencies
- No changes to `transcribe_ptt.py`, `play_ptt.py`, `build_customer_context.py`, `classify_customer.py`, or `data_extraction.py`
- No shared `documents/` folder — decoded files go to existing `media/`
- `text/plain` MIME type excluded (redundant with `body` field)

## Success Metrics

- `python decode_media_doc.py` runs without error on a customer folder
- Document entries decoded from `data:` URI → files in `media/` with `doc_` prefix
- Re-running `decode_media_doc.py` shows "No new media to extract"
- `python decode_media_ptt.py` no longer processes PDFs (ownership transferred)
- All 12 regression tests pass
- Graph/CocoIndex indexes rebuilt successfully

## Technical Approach

### Architecture
- **`media_utils.py`**: Extract 3 pure helper functions — `find_next_seq()`, `parse_data_uri()`, `get_type_prefix()` — from `decode_media_ptt.py`
- **`decode_media_ptt.py`**: Import helpers from `media_utils`; remove `application/pdf` from `MIME_EXT_MAP`
- **`decode_media_doc.py`**: New standalone script, imports helpers from `media_utils`, filters for `type="document"` only

### Key Design Decisions
- Shared module over duplication (user chose DRY approach)
- `doc_` filename prefix via existing `get_type_prefix("document")` → `"doc"`
- Pipeline position: Step 2b (after `decode_media_ptt.py`)
- Output: same `media/` folder with `doc_` prefix — no collision with `ptt_`/`img_` prefixes
- Unknown MIME types silently skipped (same behavior as existing decoder)

## Grill Outcomes

### Dimension: Assumptions
- Decision: Remove `application/pdf` from `decode_media_ptt.py`; exclusive ownership to `decode_media_doc.py`
- Rationale: Avoids first-to-run script consuming PDF entries
- Impact: `decode_media_ptt.py` MIME_EXT_MAP loses `application/pdf`; `decode_media_doc.py` owns all doc MIME types

### Dimension: Edge Cases
- Decision: `text/plain` excluded; unknown MIME types silently skipped
- Rationale: User confirmed skip for now; unknown types dealt with in the future
- Impact: MIME_EXT_MAP has pdf/doc/docx/xls/xlsx only

### Dimension: Risks & Race Conditions
- Decision: `decode_media_doc.py` positioned as Step 2b after `decode_media_ptt.py`
- Rationale: No race since they handle disjoint entry types; logical ordering
- Impact: Pipeline order: 1=data_extraction, 2=decode_media_ptt, 2b=decode_media_doc, 3=transcribe_ptt, 5=build_customer_context, 6=classify_customer

### Dimension: Alternatives
- Decision: Shared module `media_utils.py` for 3 helper functions
- Rationale: DRY; both scripts use identical helpers
- Impact: Creates `media_utils.py`; modifies `decode_media_ptt.py` to import

### Dimension: Dependencies
- Decision: No new dependencies; stdlib only
- Rationale: All required functions already in Python stdlib
- Impact: No pip install, no requirements.txt change

### Dimension: Consistency
- Decision: Follow exact same pattern as `decode_media_ptt.py` + type filter (like `transcribe_ptt.py`)
- Rationale: Same logging, atomic write, idempotency, folder selection
- Impact: Consistent user experience

### Dimension: Code Discovery
- Decision: Nothing missed; type-filter pattern confirmed by `transcribe_ptt.py`
- Rationale: `type == "document"` filter is same pattern used for `type == "ptt"` in transcription
- Impact: No additional files found needing changes
